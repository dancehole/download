# 需求与方案：相册「空间与清理」显示 OSS 占用（2026-09-16）

## 一、需求原文

> 在相册"空间与清里，能否看到OSS占用多少空间（这涉及计费问题），如果没有帮我修复

拆成两条可验收的规则：

| # | 规则 | 说明 |
|---|------|------|
| R1 | **相册级 OSS 占用可见** | 相册详情「空间与清理」里能看到该相册在 OSS 上占了多少空间（对象数 + 字节数），与「本地占用」并列 |
| R2 | **计费口径可见** | 能看到整个 OSS 桶的存储量（阿里云计费以桶为单位），并标明统计口径与延迟，避免被当成实时值 |

## 二、现状分析

当前「空间与清理」只显示**本地磁盘**占用，OSS 侧完全是盲区：

- `routers/events.py:101-103`：`GET /events/{event_id}` 里用
  `cleanup_service.calculate_local_size(event_id)` 算本地目录大小，塞进
  `data["storage_size"] / data["storage_size_text"]`。
- 前端 `js/admin.js`：`storageInfo`（清理分段）+ 折叠头摘要只消费 `storage_size`；
  `js/i18n.js` 的四条文案（`storage_occupied` / `storage_none` /
  `storage_local_cleared` / `storage_oss_cleared`）**全部是本地口径**——
  连 `storage_oss_cleared` 里的 `{size}` 指的也是本地大小。
- `oss_service.py` 只有 upload / sign / delete 能力，**没有任何统计能力**
  （无 `list_objects` 封装、无 `GetBucketStat`）。

后果：管理员点了「清空 OSS」也看不出到底释放了多少（本次修复前 `clear_oss`
静默失败更是看不见），更无法预估存储费；只有登录阿里云控制台才知道桶里有多少。

## 三、可行性探测（2026-09-16，只读真实调用，非推断）

按 `{event_id}/` 前缀 ListObjects：

```
[KX7BUB4P] 泽榆生日宴会         objects=0     size=0 B      ← 管理员已清空 OSS
[9EPBPDN8] 2023.旧约.持续更新   objects=196   size=9.0 MB
[A2FNWGY2] 小学                 objects=346   size=21.0 MB
[共享文件 files/]               objects=0     size=0 B
```

桶内顶层分布：只有上述两个相册前缀，**没有其他项目共用这个桶**
（桶 `dancehole` / 深圳），因此「桶总量 ≈ 各相册之和 + 共享文件」。

桶级统计 `GetBucketStat`（计费口径，**官方说明有约 1 小时延迟**）：

```
standard_storage        = 31,465,271 B ≈ 30.0 MB
object_count            = 542
infrequent_access_storage = 0        （无低频/归档存储）
last_modified_time      = 1789548000
```

结论：相册级（精准、实时）与桶级（计费口径、约 1 小时延迟）都取得到，权限足够。

## 四、方案

### 推荐：A. 相册级 + 桶级都显示（双层口径）

| 层 | 数据源 | 特性 | 用途 |
|----|--------|------|------|
| 相册级 | `ListObjects(prefix="{event_id}/")` 累加 size | 实时准确；**就是这个相册「清空 OSS」会释放的量** | 决定清哪个相册 |
| 桶级 | `GetBucketStat` | 计费口径；官方约 1 小时延迟，含全部前缀（本桶暂无其他项目） | 预估账单 |

按需查询 + 进程内 TTL 缓存（默认 60 秒），避免每次打开相册都打 OSS（ListObjects 有请求费用）。

### 备选

- **B. 只显示相册级**：最省事，但看不到计费总量（用户提的正是计费）。
- **C. 只显示桶级**：贴近账单，但看不出是哪个相册占的，无法指导清理动作。

### 不做（本次范围外）

- 流量费 / 请求费 / 估算金额：需要单价表 + 流量统计（OSS 无按前缀的流量接口），
  误差大易误导。本次只显示**存储量**，并在界面上写明「计费 = 存储 × 单价 + 流量 + 请求费」。

## 九、附带修复：375px 顶栏横向溢出（本需求暴露出来的既有 bug）

- **发现过程**：给 OSS 占用写 375px 断言时，先断言「设备模拟真的生效」（innerWidth≈375），
  结果发现真实 375px 下 `documentElement.scrollWidth = 488 > 375` —— 整页横向滚动半个屏。
- **根因**：`.topbar` 不换行，`.topbar-right`（`用户名(nowrap)` + 设置 + 中文/EN + 退出登录）
  的 min-content 宽度之和超过视口，flex 收缩不下来。
- **修复**：`admin.css` 新增 `@media (max-width: 760px)`：顶栏允许换行、用户名超长省略
  （`max-width: 42vw`）、收紧 padding/gap，**不隐藏任何控件**。
- **顺带修掉一个测试假绿**：`e2e-album-settings-collapse.js` 原来用
  `deviceScaleFactor: 2, mobile: true` 模拟 375px，实际 `innerWidth = 509`，
  「无横向溢出」断言恒真；已改为 `deviceScaleFactor: 1, mobile: false` 并新增
  「375px 设备模拟真的生效」断言（同类 CDP 测试都该这样自检）。
- **修复后**：375px `scrollWidth = 364 ≤ 375`，越界元素 0 个；1440px 布局无变化。
