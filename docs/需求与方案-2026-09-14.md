## 一、需求原文（用户提出）

1. **电脑端标签栏无法横向拖动**
   电脑端在照片分类过多时，应该增加类似手机端的移动分类的方法（目前情况是：手机端可以左右滑动切换分类，但是电脑 PC 端不能左右拖动）。可参考数据库新建的分类「小学」。

2. **手机端灯箱查看细节困难**
   手机端点击图片放大查看时，双击只能固定放大倍率，不能左右查看细节（手机上双击只能放大看中间，不能左右移动看照片边边细节）；电脑端希望增加滚轮放大的支持。

3. **管理页面增加权限控制管理**
   - admin 是超级管理员，可以看到所有相册和文件；
   - 可以指定某个相册生成一个「相册管理员」账号；
   - 相册管理员只可以编辑对应的相册（删除、增加和修改信息），看不到其他相册；
   - 相册管理员不能修改和查看/编辑共享文件；
   - 用户要求评估：是否有更好的方法（例如增加账号、对每个相册设定管理权限等等）。

## 三、方案

### 需求 1：PC 端标签栏横向移动

**做法：** 在 `gallery.js` 增加一个可复用的 `enableDragScroll(el)`（同时给管理端标签区复用），包含三件事：

1. **鼠标拖拽滚动**：`mousedown` → 记录起点/`scrollLeft`，`mousemove` 跟随（`cursor: grabbing`），`mouseup/mouseleave` 结束；拖动阈值 >5px 才算拖拽，避免误吞点击。
2. **滚轮横向**：`wheel` 事件 `deltaY`（含 `deltaX`）映射到 `scrollLeft`，`preventDefault` 防止整页滚动；水平滚动到两端时不拦截页面行为。
3. **可见性与左右箭头**：两侧加渐隐遮罩（`.tagbar-fade`）+ 溢出时才显示的 `‹ ›` 按钮（点击滚动 ~70% 视宽）；`scroll` 时按位置刷新箭头/遮罩；`resize` + 标签渲染后重算。

4. 附带修复：`touch-action: pan-x` 明确声明；拖拽结束后抑制一次 `click`（PC 拖拽松手不要误切分类）。

**影响文件：** `frontend/js/gallery.js`、`frontend/css/gallery.css`、`frontend/gallery.html`（新增箭头/遮罩节点）、`frontend/js/admin.js`（管理端 `#tagChips` 分类过多同样支持拖动滚动）。

**验收：** PC 打开「小学」相册分享页 → 可按住拖动、可用滚轮左右滚动、两侧箭头可见可点；手机端原有滑动不受影响；拖拽后不会误切换分类。

### 需求 2：灯箱缩放/平移引擎（手机看细节 + PC 滚轮）

**做法：** 把 `scale(2)+pan` 的写法换成标准 **translate + scale 变换模型**（`transform: translate(tx,ty) scale(s)`，`transform-origin: 0 0`），配套一个小的 `viewer` 状态机：

- 状态：`scale`（1 ~ 6，`MAX_SCALE=6`）、`tx/ty`（像素平移）、`MIN_SCALE=1`（即「适屏」）。
- **双击/双击（tap）**：在「点击点」处放大到 `2.5x`（数学上保证点击的那一点在屏幕上原地不动），再双击回到 `1x` 并复位；这是修复「只能放大看中间」的核心。
- **触摸端**：单指 `touchmove` 平移（`scale>1` 时），**双指 pinch 缩放**（以双指中点为锚点）；`scale==1` 时保持原「左右滑动切上下张」手势不变；用 `touch-action: none` 仅作用在图片上避免浏览器抢手势/页面缩放。
- **PC 端**：鼠标滚轮缩放（以光标为锚点），`ctrl/⌘+滚轮` 同样支持；`scale>1` 时按住左键拖动平移（保留原交互，改为带边界限制的 setPointerCapture 实现，指针移出窗口也不丢）。
- **边界限制（clamp）**：平移范围限制在图片实际渲染框内（`|tx| ≤ (imgW*s - stageW)/2` 之类），保证「能拖到任意一条边，但拖不出黑边」，且缩放到 1x 时自动归零。
- **切图/关闭/语言切换**：`resetZoom()` 复位 scale/tx/ty，避免上一张的位移带到下一张。
- 顺带在灯箱右下角加一组极简小控件 `− / 百分比 / ＋ / 复位`（可选、非必须），触摸/PC 都可点，方便精确查看。
- 兼容：原双击 300ms 判定改为 `pointerdown/pointerup` + 位移阈值，避免与滑动切图冲突。

**影响文件：** `frontend/js/gallery.js`（重写灯箱部分）、`frontend/css/gallery.css`。

**验收（手机 + PC 各测一遍）：**
- 手机：双击放大 → 单指可拖到图片任意边角看细节；双指可继续放大/缩小；放大状态下左右滑动**不再**误切上下张；双击/缩小回 1x 后恢复滑动切图。
- PC：滚轮以光标为中心放大缩小；放大后可拖动查看边缘；双击在鼠标位置放大 2.5x，再双击复位。

### 需求 3：权限体系（**推荐方案，比「一个相册一个账号」更好**）

用户问「是否有更好的方法」——**有**。建议不做「账号 ↔ 相册」一对一硬绑定，而是做**「账号 + 角色 + 相册授权表（N:M）」**：

```
photographer(id, username, password_hash, role, is_active, created_at)
role = 'super' | 'album'          -- 超级管理员 / 相册管理员
album_admin_acl(id, photographer_id, event_id, granted_by, created_at, UNIQUE(photographer_id, event_id))
```

**为什么更好（对比用户原始设想）：**

| 维度 | 一对一（每个相册建一个账号） | 授权表（推荐） |
|------|------------------------------|----------------|
| 一个账号管多个相册 | 不支持，要建多个账号多套密码 | 支持，勾选即可 |
| 一个相册多个管理员 | 不支持 | 支持 |
| 收回权限 | 只能删账号（连带历史操作者信息） | 取消勾选即可，账号保留 |
| 临时/轮换管理员 | 每次新建账号 + 告知密码 | 直接改授权或重置密码 |
| 后续扩展（只读、仅上传等） | 要重新设计 | `acl` 加 `perm` 字段即可 |
| 用户操作成本 | 记住 N 套账号密码 | 一套账号 |

**权限规则（后端强制，前端只是隐藏入口）：**

| 能力 | 超级管理员 super | 相册管理员 album |
|------|------------------|------------------|
| 查看相册列表 | 全部相册（显示归属人） | 仅被授权的相册 |
| 进入相册详情/上传/改标签/改设置/生成分享链接 | ✅ 全部 | ✅ 仅授权相册 |
| 清空 OSS / 删除本地照片 / 删除整个相册 | ✅ | ✅ 仅授权相册（需求：可删除、增加、修改信息） |
| 新建相册 | ✅ | ❌（避免越权创建后无人可见） |
| 共享文件（列表/上传/删除/重发链接） | ✅ | ❌ 403（需求：不能查看/编辑共享文件） |
| OSS 全局设置 | ✅ | ❌ |
| 用户管理（建号/授权/改密/停用） | ✅ | ❌ |

**同时保留用户原设想的便捷入口**：相册详情页新增「相册管理员」区块 → 点「为该相册创建管理员」→ 填用户名 → 自动生成强密码并**一次性展示**（可复制）→ 自动把该相册授权给它。这样「指定某个相册生成一个相册管理员账号」一步完成，但底层仍是授权表模型。

**落地要点：**
1. `db.py` 启动迁移：`photographer` 增 `role VARCHAR(16) NOT NULL DEFAULT 'album'`、`is_active TINYINT(1) DEFAULT 1`；现有 admin 置 `role='super'`；建 `album_admin_acl` 表（含唯一索引 + 外键级联删除相册时自动清授权）。
2. `auth.py`：JWT 增加 `role`；新增依赖 `current_user`（每次请求查库校验 `is_active`，支持即时停用）+ `require_super`；`can_manage_event(pid, ev)` 统一判定（super 通过 / album 查 ACL）。**不把权限写死在 token 里**，撤销立刻生效。
3. 改造现有接口的 `ev["created_by"] != user["pid"]`：
   - `routers/events.py`（get/list/settings/tags/share/clear-oss/clear-local/delete）
   - `routers/upload.py`（upload / upload-raf）
   - `routers/files.py` + `routers/settings.py` → 全部加 `require_super`
4. 新增 `routers/users.py`（仅 super）：`GET /users`、`POST /users`、`PUT /users/{id}/password`、`PUT /users/{id}/albums`（重设授权集合）、`PUT /users/{id}/active`、`DELETE /users/{id}`；保护规则：不能停用/删除自己，不能删除最后一个 super。
5. 管理端 UI：`state.me` 缓存角色；「共享文件」/「设置(OSS)」/「用户管理」按角色显示；新增「用户管理」视图（账号列表、角色、授权相册、重置密码、启用/停用、删除）+ 相册详情「相册管理员」区块；`i18n.js` 补中英文案。
6. `projects.md` / `README.md` 记录账号模型与开通流程（账号密码仍由超管线下告知，不落库明文）。

**风险与对策：**
- 误锁死：任何情况下不允许删除/停用最后一个 super；admin 的 super 角色不可被降级。
- 兼容：老 token 无 `role` 字段 → `current_user` 以数据库为准，老 token 不失效（仅当 `is_active=0` 才拒绝）。
- 账号泄露：相册管理员改密只能由 super 操作；后续可加「自助改密」不做在本期。
- 多 worker：权限判定全部走数据库，无进程内缓存，uvicorn `--workers 2` 下一致。

**验收：**
- 建 `album_x` 只授权「小学」→ 登录后只见「小学」；访问其他相册 API 返回 404；调 `/files`、`/admin/settings/oss`、`/users` 返回 403；上传/改标签/删相册在「小学」内成功。
- admin 登录：全部 4 个相册可见、共享文件与设置正常；能改 `album_x` 密码、能取消授权（取消后 `album_x` 立刻看不到该相册）。
- 停用 `album_x` → 其已持有 token 立即失效（401）。

### 灯箱缩放引擎要点

- 变换模型：`transform: translate3d(tx,ty,0) scale(s)`，origin 为图片中心 → 屏幕点 = 视口中心 + t + s×(图片偏移)，因此可把**任意一点**作为缩放锚点：
  `t1 = q - (s1/s0)·(q - t0)`（q 为锚点相对视口中心的偏移）
- 缩放范围 1×–6×；双击目标 2.5×；平移做边界 clamp（可拖到任意一边，但拖不出黑边；未放大时自动居中复位）
- 手势：PC 双击 / 滚轮（锚点=光标）/ 放大后拖动；移动端双击 tap / 单指拖动 / 双指捏合（锚点=双指中点，同时支持双指平移）
- 未放大时保留原有「左右滑动切换上下张」；放大后该手势自动让位给平移
- 键盘：`+`/`-`/`0` 缩放复位，放大状态下 `← →` 平移（未放大时切换上下张）

### 踩坑记录（后续同类改动可复用）

1. 箭头按钮不要只用 `@media (hover:hover) and (pointer:fine)` 判定：部分环境（内嵌浏览器、无鼠标设备上报异常的桌面）会判定为 `hover:none / pointer:coarse`，导致 PC 上箭头不显示。改为 JS 判定并加 `.sx-fine` 类：`matchMedia(...) || navigator.maxTouchPoints === 0`。
2. `.lb-img` 原来带 `transition: transform .3s`，与拖动/双指缩放冲突会严重卡顿 → 拆成只在程序化缩放（双击/滚轮/按钮）时加 `.smooth` 过渡。
3. 触摸端要 `pointerdown` 里 `preventDefault()` 抑制合成鼠标事件，否则双击 tap 与浏览器合成 `dblclick` 会重复触发（一次双击放大两次）。
4. 测灯箱缩放时不要用 `transform: scale(2) translate(...)` 的旧写法（translate 会被 scale 放大），统一用 `translate3d(...) scale(...)`。
